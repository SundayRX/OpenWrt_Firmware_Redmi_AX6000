## 布局和无线方案

| Release 中的标识 | 含义 |
|---|---|
| `immortalwrt-110m` | 普通 110m 布局；系统镜像、当前分区布局与引导必须匹配 |
| `stock` | 沿用原厂分区结构，必须使用该布局对应的系统镜像和引导；不代表原厂网页可直接安装 |
| 旧无线方案 | MTK 厂商驱动 7.6.7.2 及其配套无线固件、WARP |
| 新无线方案 | MTK 厂商驱动 7.6.7.3 及其配套无线固件、WARP |

普通 110m 的空间分配更灵活，适合安装较多插件；已有 stock 系统且空间够用时，可以继续沿用。下载前请阅读 [110m 与 stock 布局对比](flashing.md#layout-comparison)，按设备实际布局选择镜像。

不同构建可能采用不同布局和无线版本，下载时核对该次说明。无线驱动、固件与 WARP 是配套组件，不要从其他版本单独替换其中一个文件。驱动版本号更大不代表在你的网络中更稳定；这两个无线版本均属于本系列的 FW3 系统。

## 下载后使用哪个文件

先从 Release 正文已完成的构建入口下载 ZIP 与同构建标识的 `SHA256SUMS-构建标识.txt`；外层的配置摘要和包清单也带相同标识。固件压缩包包含该次实际布局的系统镜像、配套 FIP、配置摘要、包清单及校验信息。校验并解压后按以下用途选择，ZIP 内文件名保持如下形式：

| 文件 | 用途 |
|---|---|
| `firmware/` 中的 `*squashfs-sysupgrade.bin` | 匹配设备与布局的系统安装或升级；日常升级在 LuCI 中选择此文件 |
| `firmware/` 中的 `*squashfs-factory.bin`（如有） | 匹配安装入口的系统镜像；普通 110m 会提供，不需要与 sysupgrade 依次刷入 |
| `bootloader/` 中的 FIP | 初次安装或明确需要更新引导时使用；日常系统升级不必重新刷入 |
| `build-info.json`、`packages.txt`、`release-notes.md` | 查看配置摘要、实际预装软件包及版本说明 |
| `SHA256SUMS` | 核对文件完整性 |

配套引导来源为 [hanwckf/bl-mt798x](https://github.com/hanwckf/bl-mt798x)，使用方法见[作者的 U-Boot 说明](https://cmi.hanwckf.top/p/mt798x-uboot-usage/)。先按[安装与升级指南](flashing.md)核对设备和布局，再选择系统或引导文件；不要仅凭文件扩展名刷写。

## 默认设置与功能使用

默认管理地址 `192.168.31.1`、主机名 `Redmi_AX6000`、用户名 `root`、新加坡 UTC+8，未预设管理密码。首次登录请设置密码；所下载构建有不同默认值时以该次说明为准。保留配置升级继续使用已有设置。

防火墙、软件包和 Wi-Fi 管理页面是基础管理入口。各次构建的固件还可包含以下功能，具体预装内容请查看该次说明和 ZIP 内的 `packages.txt`：

- 网络与设备管理：访问控制、ARP 绑定、DDNS、设备限速、UPnP、网络加速。
- 运维与统计：定时重启、文件传输、流量统计、时间同步、系统监控、网页终端。
- 其他服务：OpenClash、UU 游戏加速器、KMS。

含有 OpenClash 界面的版本需要另行下载代理核心，再导入自己的配置。ProxyFence、WOLink 本体不随固件预装，独立安装时核对 FW3 / iptables 依赖，勿混用 FW4 安装包。硬件加速下的流量统计准确性、插件运行及设备稳定性以该版本的实际验证为准。

## 升级边界

同一布局、同一版本线的日常升级可以使用 LuCI 的保留配置选项；先保存配置备份并核对镜像。通过 U-Boot 网页安装同名 sysupgrade 镜像会重建用户数据区，应按重新安装处理。

切换 stock / 普通 110m，或迁移到 [24.10 / 6.6](24.10-6.6.md)，属于不同操作。首次跨 FW3 / FW4 迁移应清空配置并重新设置；不把旧版整包配置或内核模块直接移植过去。完整流程见[安装、升级与恢复](flashing.md)。
