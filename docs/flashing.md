# 安装、升级与恢复

[返回首页](../README.md) · [21.02 / 5.4](21.02-5.4.md) · [24.10 / 6.6](24.10-6.6.md)

本指南适用于 **Redmi AX6000 / RB06**。先判断设备当前处于原厂系统、已有匹配的 OpenWrt 系统，还是需要通过引导恢复，再选择操作入口。小米 AX6000 / RA72 不是同一设备。

<a id="layout-comparison"></a>

## 110m 与 stock：如何选择

**准备长期使用本项目固件、安装较多插件，优先考虑普通 110m；已有 stock 系统且空间够用，可以继续使用 stock。** 本项目的 24.10 / 6.6 系列仅支持普通 110m，21.02 / 5.4 系列区分两种布局，下载时以所选构建的说明和文件名为准。

布局决定路由器内部存储空间如何分配。`stock` 沿用原厂分区结构；普通 110m 在下载包中标记为 `immortalwrt-110m`。这里比较的系统区域总量均为 **110 MiB**，两者的主要区别是空间能否统一利用。

| 对比项目 | 普通 110m（`immortalwrt-110m`） | stock |
|---|---|---|
| 空间分配 | 一个 110 MiB 的区域，供内核、系统文件和用户数据共同使用 | 内核单独占用一个 30 MiB 的区域，系统文件与用户数据使用另一个 80 MiB 的区域 |
| 安装插件、保存数据 | 内核占用较小时，剩余容量可以留给系统、插件和数据，空间利用更灵活 | 内核区域的空闲容量无法直接用于安装插件；插件和数据受后一个区域的容量限制 |
| 主要优势 | 更适合功能较多的固件，以及后续安装插件、保存规则库等需求 | 已使用 stock 的设备可继续沿用现有布局，避免为了扩展空间进行布局迁移 |
| 本仓库提供的系列 | 21.02 / 5.4、24.10 / 6.6 | 21.02 / 5.4 |
| 安装要求 | 设备分区、引导和系统镜像均须匹配普通 110m | 设备分区、引导和系统镜像均须匹配 stock |

例如，stock 为内核固定划出的 30 MiB 没有用满时，其中空闲的部分仍留在内核区域，不能直接拿来安装插件。普通 110m 将这部分容量统一分配，因此在相近的固件内容下，通常能给插件和用户数据留下更多空间。

**110 MiB 不等于刷机后还有 110 MiB 可用。** 两种布局都要扣除内核、系统文件、闪存管理开销和坏块预留；具体剩余容量还取决于该版本预装了多少软件，以系统启动后的存储空间显示为准。布局调整本身不会直接提高网速、Wi-Fi 覆盖或 CPU 性能，也不代表稳定性更好。

### 按当前设备状态选择

- **已经使用普通 110m：** 继续下载普通 110m 固件，同一版本线的日常升级按下文操作。
- **已经使用 stock，空间和功能够用：** 可以继续使用本项目 21.02 系列中匹配 stock 的固件。
- **希望使用本项目 24.10 系列，或 stock 空间不足：** 先确认并完成普通 110m 的布局与引导适配，再安装相应固件。
- **仍在小米原厂系统，或不清楚现有布局：** 先按首次安装流程核对设备、备份和引导，确认布局后再选镜像。

**切换 stock 与普通 110m 属于布局迁移，不能当作普通保留配置升级。** 下载另一种布局的文件不会自动转换设备分区，也不要在 LuCI 中强制刷入不匹配的镜像。迁移前需要备份并确认引导、分区及恢复方案，具体边界见本页“U-Boot 恢复与布局边界”。

`stock` 只说明分区结构，不代表固件是小米原厂系统，也不保证原厂双系统或一键回退仍然可用。普通 110m 与 `ubootmod` 同样需要区分，本仓库不提供 `ubootmod` 固件。

## 先核对固件和备份

1. 在所选构建的说明中核对设备、系统版本、分区布局、无线版本、预装功能及验证状态。24.10 系列仅支持普通 110m；21.02 系列必须区分普通 110m 与 stock。
2. 在 Release 正文的构建列表中选定日期和配置，下载对应的固件压缩包与 `SHA256SUMS-构建标识.txt`，两者的构建标识应一致。先核对压缩包，再解压并用包内的 `SHA256SUMS` 核对准备使用的镜像。GitHub 自动生成的 Source code 压缩包不是可刷入固件。
3. 把当前配置备份、上网参数、独立插件的数据与安装包保存到电脑。另存一份在这台设备上可用、布局匹配的旧系统镜像。
4. 首次安装或涉及恢复时，准备这台设备自己的 BL2、Nvram、Bdata、Factory、FIP 及分区记录，至少留两份独立副本。Factory 包含本机无线校准信息，不能使用其他设备的备份替代。
5. 使用有线连接和稳定电源，记下当前管理地址、目标固件地址及现有引导的恢复方式。

在文件所在目录校验 SHA-256，文件名替换为实际下载的压缩包或解压后的镜像：

```powershell
Get-FileHash -Algorithm SHA256 .\实际文件名.zip
```

Linux / macOS 可以使用 `sha256sum 实际文件名.zip` 或 `shasum -a 256 实际文件名.zip`。压缩包哈希应与同一次构建的 `SHA256SUMS-构建标识.txt` 中同名文件记录完全匹配；解压后的镜像使用包内 `SHA256SUMS` 核对，不要混用不同日期的校验清单。

## 入口决定是否保留配置

`sysupgrade.bin` 是镜像文件名，配置处理由实际升级入口决定。

| 入口 | 配置和外装程序的处理 |
|---|---|
| OpenWrt / ImmortalWrt 内的 LuCI“系统 → 备份/升级”，选择保留配置 | 按系统备份清单保存并恢复设置，包含默认清单中的管理密码；外装程序不等于已备份 |
| 系统内通过 SSH 使用 sysupgrade，未指定 `-n` | 使用系统的配置保留流程；先检查实际备份清单 |
| LuCI 取消保留配置，或 SSH sysupgrade 指定 `-n` | 清空原运行配置，按新系统重新设置 |
| 本项目配套 hanwckf U-Boot 网页上传 sysupgrade / factory 镜像 | 按重新安装处理；sysupgrade 路径会重建 `rootfs_data`，原配置、管理密码和外装程序不会自动保留 |

保留配置会沿用旧 LAN 地址、主机名等设置，新固件的默认值不一定生效。保留清单外的插件身份、数据库、订阅及用户数据需要单独备份；配置备份含有敏感信息，不要公开上传。

## 已有匹配系统：日常升级

适用于同一版本线、相同设备和分区布局，且所选构建的说明没有要求清空配置的升级。

1. 登录当前系统，先把配置备份下载到电脑，并保存独立插件数据与安装包。
2. 在 LuCI“系统 → 备份/升级”上传核验过的 `*squashfs-sysupgrade.bin`，检查设备识别和兼容性结果。若提示不兼容，停止核对，不强制刷写。
3. 按需要选择保留配置并确认升级。刷写和重启过程中保持供电，等待系统重新上线。
4. 使用原管理地址或本次新设置的地址登录，检查管理密码、WAN、DNS、双频 Wi-Fi、插件、IPv6 和重启后的状态。
5. 核对外装程序是否仍存在，按本次系统匹配的 IPK 重新安装缺少的程序，再恢复必要数据。

熟悉命令行的用户可使用系统内的 SSH sysupgrade 流程，配置保留含义见上表。日常系统升级通常无需重新刷入 FIP。

## 首次跨 21.02 / FW3 与 24.10 / FW4 迁移

先确认设备已经具备普通 110m 布局及匹配引导。**首次跨这两条版本线时取消保留配置**，重新设置 WAN、LAN、DHCP 和 Wi-Fi，再逐项迁移用户数据。旧版 stock 设备需要另行处理布局，不能直接套用本节。

旧系统的完整配置备份用于回退原系统，不整包导入另一版本线。旧无线配置文件、iptables 规则、启动脚本及内核模块不要直接覆盖新版文件。独立插件须核对 FW3 / FW4 分支和依赖；恢复身份或配对数据时使用同一次、同一台设备的完整备份。

先确认基础上网和 Wi-Fi 正常，再恢复代理及其他服务。出现问题时保留现象和日志，使用匹配布局的旧镜像回退；备份只有在与其对应的系统中恢复，才有明确的兼容依据。

## 原厂首次安装

原厂首次安装包含取得管理权限、备份本机分区、确认引导与布局、安装系统及首次配置，不能按普通 LuCI 升级处理。原厂版本会影响取得管理权限的方法，本页不提供可直接套用的分区写入命令。

引导来源和操作依据使用 [hanwckf/bl-mt798x](https://github.com/hanwckf/bl-mt798x) 及[作者的 U-Boot 使用说明](https://cmi.hanwckf.top/p/mt798x-uboot-usage/)。完成设备身份、备份与恢复路径核对后，再选择匹配 Redmi AX6000 的引导和固件。

21.02 系列固件包附与该包布局匹配的 FIP；24.10 系列不附引导，要求设备已具备匹配的普通 110m 引导。FIP 是引导文件，系统镜像是另一类文件，分别使用对应入口。不要把本项目 sysupgrade / factory 文件直接上传到小米原厂管理页面。

## U-Boot 恢复与布局边界

系统无法启动但引导恢复页可用时，按已安装引导的说明进入恢复页面，使用匹配设备与当前布局的系统镜像重新安装。官方说明中的 Redmi AX6000 恢复地址为 `192.168.31.1`，电脑使用同网段静态地址；设备如果更改过引导设置，以现场配置为准。恢复页地址与系统 LAN 地址是两套设置。

**通过配套 U-Boot 安装即使使用 sysupgrade 文件，也不会替你保留原设置。** 完成后重新设置密码和网络；原数据只能从事先保存的备份恢复。

stock、普通 110m 和 `ubootmod` 不能靠在 LuCI 上传另一布局镜像直接转换。布局变更或原厂恢复须先明确引导支持、分区映射、本机备份及恢复方案，按对应引导文档单独处理。不要擦写或替换不相关的校准、身份分区，也不要把另一台路由器的备份当作通用恢复包。

引导恢复页也不可用时，停止重复试刷，保留设备状态并确认是否需要串口或其他恢复方式。
