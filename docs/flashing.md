# 安装、升级与恢复

[返回首页](../README.md) · [21.02 / 5.4](21.02-5.4.md) · [24.10 / 6.6](24.10-6.6.md)

本指南适用于 **Redmi AX6000 / RB06，普通 110m 布局**。21.02 和 24.10 两个系列均只发布这一布局的固件，小米 AX6000 / RA72 不是同一设备。

先确认当前设备属于哪种情况：

- 已安装本仓库普通 110m 固件，且管理页面可用：按[网页升级步骤](#web-upgrade)更新或回退；跨两个系列切换时取消保留配置。
- 仍在使用小米原厂系统：按[首次安装](#原厂首次安装)准备，不能套用系统网页升级步骤。
- 系统无法启动：先确认[引导恢复入口](#u-boot-恢复与布局边界)是否可用，再选择匹配布局的镜像。

<a id="layout-comparison"></a>

## 安装前确认普通 110m 布局

普通 110m 在发行说明中标记为 `immortalwrt-110m`，ZIP 文件名中简写为 `110m`。它将系统区域统一分配给内核、系统文件及用户数据，使剩余空间更便于用于插件和数据。

**110 MiB 不等于刷机后有 110 MiB 可用。** 内核、系统文件、闪存管理和坏块预留都会占用空间，实际余量以启动后的显示为准。

<a id="按当前设备状态选择"></a>

本仓库不发布 stock 或 `ubootmod` 固件。使用这些布局或小米原厂系统的设备，不能直接按本文的网页升级步骤刷入普通 110m 镜像；须先按适用的安装方案处理分区和引导。**上传固件不会自动完成布局转换。** 不清楚当前布局时，先确认分区与引导信息，再决定安装方式。

<a id="verify-download"></a>

## 先核对固件和备份

1. 在发行说明中核对型号、布局、系统与无线版本、预装功能、默认地址和已知限制。
2. 下载该版本的固件 ZIP，核对完整 SHA-256 后解压，再用包内 `SHA256SUMS` 校验要刷写的镜像。
3. 把配置备份、上网参数、独立插件的数据与安装包保存到电脑，同时保存一份在本机可用、布局匹配的旧固件。取消保留配置会清空原网络、Wi-Fi 和管理密码等设置，先记下重新配置所需的信息。
4. 首次安装或涉及恢复时，准备这台设备自己的 BL2、Nvram、Bdata、Factory、FIP 及分区记录，至少留两份独立副本。Factory 含本机无线校准信息，不能用其他设备的备份替代。
5. 使用有线连接和稳定电源，记下当前地址、目标默认地址及已有引导的恢复方式。

### ZIP 内使用哪个文件

| 文件 | 用途 |
|---|---|
| `firmware/*squashfs-sysupgrade.bin` | 在系统内更新或回退，必须匹配设备和当前布局 |
| `firmware/*squashfs-factory.bin`（如有） | 用于匹配的首次安装或恢复入口，无需与 sysupgrade 依次刷入 |
| `bootloader/` 中的 FIP（仅 21.02 附带） | 独立引导文件，初次安装或明确需要更新引导时使用；日常系统升级无需重刷 |
| `release-notes.md` | 该版本的系统、内核、默认设置和插件说明 |
| `packages.txt` | 实际预装软件包及版本 |
| `SHA256SUMS` | 包内文件的 SHA-256 校验清单 |

**GitHub 自动生成的 Source code 压缩包不能刷机。** 历史版本可能直接提供 `.bin` 或单独的校验清单，按原发行说明使用，不混用不同版本的文件。

在文件所在目录执行，文件名替换为实际下载的 ZIP 或解压后的镜像：

```powershell
Get-FileHash -Algorithm SHA256 .\实际文件名.zip
```

Linux 使用 `sha256sum 实际文件名.zip`，macOS 使用 `shasum -a 256 实际文件名.zip`。将完整结果与发行说明或 GitHub 附件的 `sha256:` 摘要比较；镜像则与同包 `SHA256SUMS` 比较，不只核对前几位。

<a id="web-upgrade"></a>

## 已刷机用户：推荐从系统网页更新或回退

适用于管理页面可正常登录、已安装本仓库普通 110m 固件的 RB06。目标镜像必须通过系统兼容性检查；无需进入 U-Boot 或重新刷写 FIP。此流程用于系统更新或回退，不改变分区布局。

| 操作 | 固件与配置选择 |
|---|---|
| 同一系列内更新 | 普通 110m 的 `sysupgrade.bin`；版本说明允许时，可按需保留配置 |
| 21.02 / 5.4 → 24.10 / 6.6 | 两侧均为普通 110m，使用 24.10 的 sysupgrade，取消保留配置 |
| 24.10 / 6.6 → 21.02 / 5.4 | 两侧均为普通 110m，使用 21.02 普通 110m 的 sysupgrade，取消保留配置 |
| 回退同一系列内的旧版 | 普通 110m 旧镜像，建议取消保留配置，再重新设置或恢复匹配备份 |

1. 完成前述备份和校验，登录当前系统的“系统 → 备份/升级”。
2. 上传解压后的 `*squashfs-sysupgrade.bin`，不要上传整个 ZIP、factory 或 FIP。
3. 核对设备识别和兼容性结果。提示不兼容时停止刷写，重新核对设备和镜像，不强制跳过检查。**跨 21.02 与 24.10 时取消“保留配置”及其他保留设置的选项。**
4. 确认后保持供电和有线连接，等待写入、重启，勿因管理页面断开而中途断电。
5. 未保留配置时，让电脑重新获取地址，以目标默认地址登录，重新设置密码、WAN、LAN 和 Wi-Fi；保留配置时沿用原地址与设置。
6. 检查 WAN、DNS、双频 Wi-Fi、IPv6 和重启后的状态，再安装匹配的独立插件并恢复必要数据。

熟悉命令行的用户也可使用系统内的 SSH sysupgrade。系统无法启动或管理入口不可用时，按下文 U-Boot 恢复流程处理。

## 配置与插件怎么恢复

| 操作方式 | 设置与外装程序 |
|---|---|
| LuCI 选择保留配置，或 SSH sysupgrade 未指定 `-n` | 保留实际备份清单中的设置和管理密码；外装程序需要另行准备 |
| LuCI 取消保留配置，或 SSH sysupgrade 使用 `-n` | 清空原运行配置，按新系统重新设置 |
| 配套 hanwckf U-Boot 网页安装 sysupgrade / factory | 按重新安装处理，原配置、密码与外装程序不会自动保留 |

**21.02 / FW3 与 24.10 / FW4 之间每次切换都取消保留配置。** 完整备份用于回退对应系统，不整包导入另一版本线。无线配置、iptables 规则、启动脚本和内核模块也不要直接跨版本覆盖。

插件身份、配对数据、数据库和订阅可能不在系统备份清单内，需单独备份。恢复时使用同一台设备的完整数据，并核对插件的 FW3 / FW4 分支与依赖；备份可能含密码等信息，请保存在自己的电脑上。

不保留配置后，重新设置网络和 Wi-Fi；不要为了恢复旧地址或密码而将另一系列的完整备份导入新系统。回退到原系列时，才使用为该系统保存的匹配备份。

先确认基础上网和 Wi-Fi，再恢复代理及其他服务。出现问题时按[反馈说明](../README.md#反馈)记录；管理页面仍可用时，可从同一入口回退匹配布局的旧镜像，再恢复该系统对应的备份。

## 原厂首次安装

首次安装需要取得管理权限、备份本机分区、确认引导与布局、安装系统并完成初始设置。原厂版本会影响取得权限的方法，不能套用普通 LuCI 升级步骤。

引导及操作依据见 [hanwckf/bl-mt798x](https://github.com/hanwckf/bl-mt798x) 和 [hanwckf 的 U-Boot 使用说明](https://cmi.hanwckf.top/p/mt798x-uboot-usage/)。21.02 包附普通 110m 配套 FIP；24.10 不附引导，要求已有匹配的普通 110m 引导。FIP 与系统镜像分别使用对应入口，不要把这里的 sysupgrade / factory 文件直接上传到小米原厂网页。

## U-Boot 恢复与布局边界

系统无法启动但引导恢复页可用时，按已安装引导的说明，使用匹配设备与当前布局的系统镜像重新安装。hanwckf 说明中的 Redmi AX6000 恢复地址为 `192.168.31.1`，电脑使用同网段静态地址；更改过引导设置的设备以现场配置为准。恢复页地址与系统 LAN 地址是两套设置。

**通过配套 U-Boot 安装即使使用 sysupgrade 文件，也不会保留原设置。** 完成后重新设置密码和网络，原数据从事先保存的匹配备份恢复。

布局变更或原厂恢复按对应引导文档处理，不属于普通系统升级；不要擦写无关的校准、身份分区，也不要使用另一台设备的备份。

引导恢复页也不可用时，停止重复试刷，保留设备状态并确认串口或其他恢复方式。
